# Rust workspace reader and corpus

2026-10-18 · RUST-T02. Library capability; the CLI retains the foundation interface until RUST-T04. No model, persistence, approval, note mutation or network capability is introduced.

`WorkspaceCorpus::open(selected, state_root)` fixes one canonical selected root and pins its directory descriptor. Only an explicitly selected root may resolve through a symlink. The caller must supply the external absolute application-state root; this adapter checks existing state components for symlinks and rejects either direction of state/workspace overlap. It creates no state and imports nothing. State permissions, credential storage, persistence and revalidation before future state writes remain later work.

## Read authority

The Unix adapter uses [rustix openat](https://docs.rs/rustix/1.1.5/rustix/fs/fn.openat.html) relative to held descriptors. Every ancestor is opened separately with DIRECTORY and NOFOLLOW; regular files use RDONLY, NOFOLLOW and NONBLOCK. No path-based descendant open or `/dev/fd` reopening occurs. Enumeration uses descriptor-relative directory iterators. Symlinked descendants are skipped, including links to another location inside the workspace. Special files are skipped; replacement with a FIFO cannot block opening. Identity checks reject replacement between entry inspection and opening. Before publishing a complete scan, every opened path is reopened from the root with no-follow component checks and its device/inode compared; the selected root identity is checked before and after scanning. A moved/replaced root invalidates the reader. No raw descriptor escapes the adapter.

These are capability-scoped reads, not an atomic filesystem snapshot. Ordinary concurrent in-place edits can overlap a read; unrelated editors do not honor Synapse locks. An editor can change a file immediately after validation. Future writes require their own fresh snapshot/lock/journal protocol. A detached ancestor may be read through a descriptor held before its rename, but its result is discarded if its root-relative identity no longer matches at final validation. Filesystem hard links are ordinary regular files; this does not sandbox another process with independent filesystem permissions. Release filesystem/platform qualification remains separate.

## Policy and metadata

`CorpusPolicy` carries distinct validated instruction/inbox paths, excluded folder prefixes and exact tag values. Defaults protect `Synapse/Instructions.md` and `Research.md`. Hidden components (including VCS/application directories), configured folders and control paths are skipped before descent or reading. Tags and `synapse: ignore` / legacy `vault-synapse: ignore` are checked before publishing documents. Controls can be absent; retrieval does not require setup. Path exclusions compare ASCII case-insensitively, conservatively protecting default controls on case-insensitive filesystems. Tags compare exact strings; non-ASCII configuration must use actual on-disk Unicode spelling. File syntax requires lowercase `.md` and rejects absolute/traversing paths, backslashes, colons and controls.

Frontmatter is a YAML mapping between `---` lines. Description, tags and aliases meet SPEC bounds; aliases must be present, with `[]` allowed. Body text alone supplies evidence. Missing/malformed fields, invalid UTF-8 and oversized notes produce only an attention path; no body survives that boundary. YAML references/custom tags are conservatively refused before deserialization, including flow-collection references and plain-scalar apostrophes; this prevents amplification through aliases. Unsupported reference/tag syntax requires manual metadata repair. Quoted literal punctuation remains data. Frontmatter has a 16,384-byte ceiling. No metadata repair or write is performed.

Limits are named in `Limits`: at most 1,000,000 bytes per file, 32,000,000 aggregate bytes read, 10,000 encountered entries, depth 32 by default (hard ceiling 64), and 20 results (hard ceiling 100). Entries are counted even when their filename is not UTF-8. Configured lower limits are supported; excessive configuration is refused. File oversize yields attention; aggregate, enumeration, depth or graph overflow refuses the entire result. A failed scan never exposes partial results. Memory includes bounded temporary parsing, lowercasing, source/frontmatter retention and graph data; 32 MB is the source-byte budget, not a process-RSS promise.

## Retrieval and freshness

`Corpus` stores the permitted documents as a bounded lexical corpus. Queries match case-insensitive body/title, relative names, descriptions, tags and aliases. Rank is matched-term count with deterministic path ties. Queries are bounded to 1,024 bytes and 16 terms. Metadata may discover a document but cannot become a quote. A hit mints an opaque instance/generation/ordinal/line ID. Resolution rereads the corpus, verifies instance and generation, rechecks policy, and returns one exact body line and its original one-based Markdown line number. Lines over 4,096 bytes are refused rather than truncated. These passages are evidence candidates; factual answer support is a later agent responsibility.

The link graph recognizes inline local Markdown destinations and wikilinks, optional fragments and wiki labels. Markdown `./` is normalized; traversal, URLs and missing/excluded destinations grant no edge. Wiki paths resolve relative to the source folder, then workspace-root paths. Ambiguous global-basename guessing is absent. Reference-style Markdown links and complex escaped/parenthesized destinations are not parsed yet. The graph never performs filesystem reads of link targets. It is bounded to 256 syntactic links per note and 20,000 total; overflow refuses the corpus. Backlinks use the same permitted graph.

`refresh()` is the polling watcher: complete bounded scans compare exact retained body/frontmatter/metadata and attention membership, without trusting mtime granularity. It reports change and advances the generation. Search, links, backlinks, attention and evidence resolution all poll; policy replacement immediately clears the snapshot and invalidates IDs. Failed scans also invalidate. The future interactive session schedules polls; there is no background watcher thread or note-text event log. Unchanged excluded bytes do not need a retained snapshot because they cannot yield evidence. Source/diff display and terminal sanitization remain separate from content-free diagnostics.

## Dependency review

[Cargo.lock](../Cargo.lock) pins dependencies; [the inventory](../scripts/rust-dependencies.json) freezes exact package versions, resolved features, licenses and build-script flags for the full Cargo metadata graph, including unbuilt target/derive dependencies. Core adds pure `serde_yaml_ng` 0.10.0 (MIT, MSRV 1.64); adapters add `rustix` 1.1.5 with fs/std (MIT option, MSRV 1.65). Workspace code continues to forbid unsafe Rust. These libraries have transitive unsafe implementation code: rustix/OS bindings and the Rust libyaml port. No C compiler, native libyaml dependency or runtime bridge is added. The macOS native binary links system libiconv and libSystem; clean install and system linking are checked separately.

Reviewed build scripts: libc detects compiler/platform versions; rustix probes compiler capabilities and removes its probe artifact; serde/serde_core detect compiler versions and generate private Rust modules in Cargo OUT_DIR. Proc-macro2 and quote scripts in the metadata graph probe compiler features/versions; derive is not enabled by the application. Scripts may execute rustc or configured compiler wrappers at build time; libc has FreeBSD/Emscripten-specific version probes outside our claimed targets. No product runtime shell or network is introduced. Transitive license choices include MIT/Apache-2.0, Ryu's Apache-2.0/BSL-1.0 and unicode-ident's combined Unicode-3.0 terms. These are development dependencies requiring inclusion of their notices in future redistributed source/binary licensing work at RUST-T09; the existing development artifact is not a release license qualification.

The boundary check separately enforces normal and test crate edges, local build-script absence, external inventory, adapter-only syscalls, read-only corpus open flags, the separate lease-only state lock exception, allowlisted provider transports and structured-model boundaries. Lexical guards and mutation probes supplement compiler and race tests; they are not a Rust parser or a complete authority proof.
