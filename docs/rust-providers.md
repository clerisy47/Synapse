# Rust provider boundary

2026-10-19. Native provider boundary; qualification evidence is linked below.

All public model operations go through `JobQueue`. The underlying provider's HTTP methods are private. Health-only constructors cannot disclose passages: evidence selection requires a workspace-bound constructor. Permitted body coordinates, metadata/tag exclusions, protected control paths and exact passage bytes are reread immediately before template rendering, tokenization, completion and response delivery. The application attaches trusted evidence IDs rather than filesystem paths; note text can mention paths as untrusted content. Configuration is fixed for a process; policy changes require rebuilding the provider composition.

The local origin is exactly `http://127.0.0.1:18080`, with fixed routes. Proxy discovery and redirects are disabled. Health verifies a Bonsai 9B alias, PQ2 filename, 4,096 context and one slot; these server-reported fields do not cryptographically attest model weights. No model/runtime process is launched and no files are downloaded. Thinking is disabled explicitly in the local request.

The local builder uses llama.cpp's native schema envelope, documented in the [upstream server contract](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md). The remote builder uses the OpenRouter JSON Schema envelope. Response validation accepts only the strict status/evidence-ID shape with bounded, unique, application-owned IDs. No model-produced quote, path, grant or approval is trusted. Metadata fields and one research paragraph are separately bounded values that can only become local review proposals. Selection is a retrieval primitive; chat/research orchestration is separate.

OpenRouter requires explicit provider/model selection and disclosure consent before credential access. Its endpoint is fixed HTTPS, no proxy/redirect/fallback, and credentials come solely from `OPENROUTER_API_KEY`. The builder requires parameter support and disables routed-provider fallback. No remote call has been made during local verification; a live remote call requires the user's explicit selection and disclosure consent.

The queue permits 16 waiting jobs and one active job. Interactive requests have priority, with a background opportunity after four interactive jobs. Queued cancellation removes the ticket; cancellation suppresses an active late result. Synchronous HTTP operations retain their slot/lease until completion or deadline; cancellation does not immediately interrupt a blocked HTTP syscall. A model job has a shared 45-second deadline across its provider requests, preceded by at most 30 seconds in the queue. A local cross-process lease waits at most 30 seconds within the job budget. Its private 0600 no-follow lock file lives under private 0700 external application state and is never unlinked. The lease coordinates all Synapse workspaces using this local server. Arbitrary separately launched clients do not honor Synapse's lease.

Inputs are capped at 1,024 question bytes, eight passages and 2,560 serialized message bytes. Local chat-template rendering and tokenization verify the exact prompt against context plus 128 reserved selection output tokens (512 for bounded metadata/research jobs). Inputs are refused rather than truncated. Remote input uses a conservative byte budget with context headroom; chosen remote models must support the strict schema. Responses are bounded to 65,536 bytes and selection content to 4,096 bytes. Truncated completions are rejected. Errors are fixed public codes and contain neither HTTP bodies nor prompts.

Initial provider evidence: strict-response/consent/budget tests, eight-thread queue serialization, queued cancellation, active late-result suppression and a two-process runtime-lease test. An isolated-home synthetic local health/selection test passed after correcting the local schema envelope. This is one supported fixture and does not close the quality, unsupported-answer or research gates. Full test totals and final task status belong to PROGRESS.md and PLAN.md.

Metadata requests use a bounded body excerpt, never unknown YAML fields. Research jobs use the selected captured span, formatting prose and trusted destination IDs, with fresh inbox/instructions hashes at every boundary. Draft/insufficient shapes are discriminated. Local selection grammar admits only supplied IDs; all responses receive independent strict validation. The MCP request cancellation budget shortens per-job transport deadlines. Broader final quality/privacy and live research evidence is in [native qualification](evidence/native-qualification-2026-10-19.md); live remote quality is not claimed.
