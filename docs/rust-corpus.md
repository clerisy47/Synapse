# Rust workspace and corpus evidence

2026-10-18, local macOS aarch64, Rust 1.85.1. This implements the read-only corpus library; user-facing chat/search orchestration belongs to T03/T04.

The root is explicitly selected, canonicalized once, then opened from `/` one descriptor-relative component at a time with directory/no-follow flags. Descendant opens use held directory descriptors, one validated component at a time. Every directory and final Markdown file rejects symlinks. Root selection through a symlink remains allowed: only the resulting canonical path is used. No raw descriptor reaches core or terminal code. Regular-file checks and nonblocking opens reject special files. UTF-8 and file-size checks precede ingestion. There is no writer or network transport in this implementation.

Root/state overlap is refused before traversal. State location resolution performs no directory enumeration and no persistence. Hidden directories/files (including VCS internals), configured excluded folder prefixes and the distinct configured instruction/inbox paths are omitted before reads. Tag exclusions and `synapse: ignore` / legacy `vault-synapse: ignore` (also accepting nested `{ignore: true}` forms) are checked before indexing. Ordinary notes need bounded description/tags/aliases. Invalid metadata is available only through the separately filtered local attention projection. Existing state is never imported.

The lexical corpus stores exact bytes plus validated discovery metadata, body line offsets, local Markdown/wikilinks and modification time. Link discovery ignores URLs and rejects traversing destinations. Ambiguous title-only wikilink resolution and URL fetching are not implemented. Links resolve relative to their source folder. Recent results use filesystem modification seconds and deterministic path tie-breaking. Metadata matches may select a body passage, but metadata is never returned as factual body evidence.

All evidence, graph, recent and attention projections recheck current access and bytes before returning results. A changed note is omitted until refresh, rather than citing stale coordinates. A polling watcher hashes bounded current contents every 250 ms, exposing an invalidation generation; refresh discards/rebuilds the corpus. The hash is a change hint and grants no authority. Fresh byte comparison remains mandatory. Polling supports same-size changes without trusting modification times and joins its worker on drop. Terminal orchestration must connect the watcher to session refresh in T04.

Named provisional bounds: 128 KiB per Markdown file, 10,000 visited directory entries, depth 32, 16 MiB total input per index/watch pass, eight projected results, six lines/1,200 characters per excerpt, 4,096 bytes/32 terms per lexical question. Over-budget traversal/indexing fails closed. Oversized/invalid files stay outside retrieval. YAML's upstream recursion/repetition limits are retained; additional metadata fuzz/resource qualification remains useful before release.

Verification: `cargo test --locked` includes real temporary-filesystem tests for invalid/oversized data, path traversal, symlinks, replaced ancestors, exact line coordinates, stale evidence, folder/control/tag exclusions, ignore markers, state overlap, links/backlinks/recent results, polling refresh, watcher teardown, depth and aggregate memory limits. The concurrent replacement case performs 500 swaps and 2,000 reads and accepts only original in-root bytes or refusal, never the outside sentinel. Pure tests cover malformed/deep YAML and required metadata value types.

The descriptor strategy protects against symlink replacement, not hostile mount manipulation or arbitrary kernel/privileged-process behavior. A selected root's held descriptor continues to represent that selected directory if it is renamed; Synapse never follows a replacement symlink to a different directory. Linux execution and release filesystem qualification remain pending. No write-race, crash recovery, model-quality or MCP gate is closed by these read tests.
