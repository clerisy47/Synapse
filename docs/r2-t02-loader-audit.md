# R2-T02 — Editable control loaders

> Historical evidence: Security.md support was removed on 2026-10-17. Use [current access contracts](control-contracts.md) for active requirements.

## Goal and implementation plan

Load user-owned Instructions.md and Security.md through VaultPort without modifying
vault files. Preserve strict deterministic contracts and ordinary search privacy.
Implement in ordered slices:

1. Instructions module: strict exact-text YAML parsing, full-content hashes,
   immutable validated snapshots, immediate version invalidation, stale-read and
   disposal guards, missing-only starter proposals, timezone calendar routing.
2. Config/policy: defaults and tolerant old-settings migration, configurable
   canonical noncolliding paths, control/inbox exclusion before corpus reads.
3. Host/UI: settings fields, redacted status command, inert exact starter review,
   composition/lifecycle wiring, repository starter generation for the bundle.
4. Test loader, routing, migration, ingest and DOM behavior. Run required checks,
   build and injected-host smoke, then update PLAN/PROGRESS and deliver.

Main.ts remains wiring. No model, network, policy grant, approval authority or
vault write is introduced. Starter assets are bundled by a reproducible generator;
their equality with repository assets is tested. YAML is a direct pure-parser
dependency and its errors are never exposed as diagnostics.

## Runtime behavior and limits

The control store loads both files explicitly and publishes a monotonically
increasing revision. Create/modify/delete/rename events invalidate both snapshots
synchronously before reload. Generations prevent old reads from restoring stale
state; disposal removes listeners and invalidates outstanding reads. Snapshot
hashes cover complete exact text, including prose/line endings. Ready snapshots
are recursively frozen. Case aliases and colliding filenames fail closed.

Load states are loading, missing, invalid, unavailable, or ready. The command
`Control file status` exposes these states without content or exception details.
Conflicting destination/control paths invalidate instructions. Internal ordinary
search continues with existing exclusions; recipient-policy integration is R2-T03.

The command `Review missing starter files` shows exact contents for missing
Instructions/Security files. It has no apply or approval button and never
creates, updates or overwrites anything. Presence checks conservatively consider
case aliases. The future setup adapter must check actual filesystem/editor state,
including folders/non-note collisions, and absence immediately before creation.
Research.md is excluded but is not generated by this setup flow. Manual creation
is possible from the review text until the restricted adapter lands in R3-T04.

Settings path edits reject invalid/colliding paths visibly. Old or malformed
persisted settings safely fall back to default control paths. Changed paths
rebuild loaders and corpus; prior listeners are disposed. Stored-file events drive
loading; application-time unsaved buffer revalidation remains R3-T04.

Daily routing accepts an explicit Gregorian ISO calendar date, numeric UTC
instant, or exact `today`/`yesterday`/`tomorrow` token with an injected clock instant.
The configured IANA timezone determines the local date. Relative shifts use
calendar arithmetic, including DST/leap/year boundaries. Locale dates, free prose,
offset-free timestamps and invalid dates fail. Relative dates should be resolved
once when generating a proposal; later approval binds the resolved path.
