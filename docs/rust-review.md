# Native review and recovery

`setup`, `metadata review` and `research review` require local input/output terminals. `--preview` pages through every full before/after file without applying. `next` advances pages; `accept` selects a file. Default review then asks for the exact word `Apply`. EOF, piped input, JSON, model output and command-line flags cannot approve writes. All source bytes, target bytes, identities, parent identities, policy and provider configuration bind the in-memory review.

Setup proposes only missing configured controls and explicitly displays missing parent directories. Existing controls are never overwritten. Research capture persists an exact selected span with source/selection hashes in private external state; capture never consumes the inbox. Research destinations come from versioned Instructions metadata, use trusted IDs in model requests, and require an explicit YYYY-MM-DD date for daily routes. Model values cannot supply paths. Metadata proposals insert missing fields while preserving existing fields, frontmatter, body and line endings. Invalid existing fields require manual repair.

Native state lives outside the workspace in an owner-only workspace namespace. Captures are bounded at 20. Recovery retains full before/after content: 20 records, 4,000,000 serialized bytes, 30 days for resolved entries. Unknown outcomes remain and block new writes. Retained research selection hashes prevent duplicate processing even when other inbox text changes. Clearing history discards this protection. State is not encrypted and external backups are separate.

Apply holds an interprocess workspace lock, durably saves intent, checks snapshots again, stages bytes on the target filesystem, synchronizes them and atomically replaces the exact target name. New files use exclusive no-replace rename. Existing target ownership and permissions are preserved; hardlinked targets are refused. Directories and symlinks are never note targets. Internal staging names are hidden non-Markdown files, not user notes; an interrupted attempt can leave one behind. Reconciliation reads actual target bytes and records applied/refused/unknown, never automatically replays. Cancellation after intent also requires reconciliation.

An unrelated editor can change a name between the final check and POSIX replacement. The native implementation does not claim filesystem compare-and-swap, protection against privileged mount replacement, or control over external editors. Fresh descriptor-relative traversal, no-follow checks, parent identity comparison and exclusive creates narrow the race. Application writers serialize with each other.

`recovery --workspace ROOT` lists outcome IDs. `--revert ID` creates a fresh exact review when current bytes still equal the recorded result. New notes revert to empty files; no note deletion occurs. Setup control creation cannot be reverted through the ordinary-note port. `data clear --workspace ROOT` requires local explicit `Clear`, preserves notes/configuration, clears captures/history and invalidates pending approval epochs.

Verification includes real filesystem/subprocess persistence, pre-attempt and post-write intent reconciliation, divergent outcome refusal, stale snapshots, symlink/control refusal, cancellation, and real PTY preview/Apply. Live Bonsai proposal tests are separate opt-in checks; mocks do not prove model quality. MCP lifecycle and release qualification are separate tasks.
